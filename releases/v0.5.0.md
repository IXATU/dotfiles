# v0.5.0 - IXATU Herdr Workday

**Date:** 2026-10-23
**Previous release:** v0.4.0

## Highlights

- Add `ixatu-day` as the optional daily entrypoint for a persistent, isolated Herdr session named `ixatu`; leave native `herdr` and the experimental `ixatu-lab` session unchanged.
- Declare six semantic workspaces: Tools/DC Remote, Dotfiles/Updates, DevX/Vault Status, Operations/Shell, Billing/Shell and Market Data/Shell.
- Start or reuse Desktop Commander without duplicating a running process. Run `dotfiles-update` and `uv run devx vault status` at most once per local date and device, with persistent status and failure reporting; never publish the Vault automatically.
- Reconcile missing workspaces and tabs without deleting or modifying occupied panes. Skip unavailable repository directories with a warning; never clone repositories automatically.
- Keep commands readable in Powerlevel10k tabs by invoking short internal `ixatu-day --run-task` commands, and provide a non-mutating `ixatu-day --dry-run`.
- Make the launcher reproducible on additional WSL workstations through an explicit Chezmoi symlink; neither `make install` nor `dotfiles-update` implicitly applies it.

## Usage / replication

On a new Ubuntu/WSL2 workstation, sync `~/dotfiles` from `main`, ensure Herdr is installed (e.g. `make install-ai-workspace`) and explicitly publish only the launcher: `dotfiles-apply --apply ~/.local/bin/ixatu-day`. Then run `ixatu-day --dry-run` and `ixatu-day`. Uncloned project directories are omitted with a warning. `ixatu-day` will never launch coding agents automatically.
